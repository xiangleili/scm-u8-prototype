1. 字段边界与最小必要对接原则（存货、客户、供应商）：
• 系统边界明确：业务系统与用友 U8 各自管理本系统特有的业务属性。业务系统多出的内部跟踪字段变更时不触发向 U8 同步；U8 自身财务特有字段由 U8 独立管理，业务系统不予干涉。
• 同步触发条件：仅当U8 必需的对接字段（如存货名称、规格型号、计量单位；客户/供应商名称、纳税人识别号、开户行账号等）发生修改时，才触发状态更新为【待同步】并调用 U8 修改接口增量更新。

2. 档案生命周期流转（新增 / 编辑 / 停用 / 启用）：
• 新增建档：业务系统新增保存 ➔ 直接调用 U8 档案新增接口创建主数据 ➔ 成功置为【已同步】，异常置为【同步失败】。
• 属性修改：U8 必需对接字段变更 ➔ 直接调用 U8 档案修改接口更新属性。
• 停用：业务系统停采/停产/终止合作 ➔ 直接调用 U8 停用接口进行逻辑停用（写入 bStop=1，物理保留以保障历史单据核算）。
• 重新启用：业务系统恢复物料采购或恢复合作 ➔ 直接调用 U8 启用接口恢复正常使用。

3. 部门档案与仓库档案（U8 为权威源，只读同步拉取）：
• 部门档案：以用友 U8 财务部门树为权威源。由财务在 U8 统一建档管理，SCM 仅只读拉取镜像并在单据中作为经办部门选用，SCM 本地不进行新增、编辑与停用。
• 仓库档案：以用友 U8 仓库档案为基准，宝应仁恒仓储现场直接通过数据库视图查询共享同一套 U8 仓库编码，全链路统一编码制，无需维护三方对照转换表。彻底移除计价方式、物理库区与仓库类型等非标伪字段。
• 专管部门解耦：客户档案与供应商档案中无需维护固定销售/采购部门，单据入账核算主体由单据表头经办部门动态决定，避免主数据冗余耦合。

4. 状态机与基础档案轻量交互规范：
• 三态闭环：状态全局收敛为标准三态【待同步】、【已同步】、【同步失败】，彻底废除“持续失败/熔断停机”过度设计。
• 基础档案免详情：五大基础档案（存货、客户、供应商、部门、仓库）的核心属性在表格行中已完整呈现，不提供多余的【详情】弹窗。待同步单据展示【同步】按钮，同步失败展示【重试】与【诊断】，已同步行或只读镜像行操作列展示【—】。
• 状态枚举统一：部门与仓库档案状态严格统一为【启用】与【停用】两态。全局操作动词收敛为「同步」、「重试」、「诊断」。

一、三方系统定位、核心原则与入账时间机制
● 业务系统 (中台)

U8 唯一写入入口。下发出入库指令，接收执行明细与入账时间，按合同订单补齐单价与税率，推送单据至 U8。

● 仓储系统 (宝应仁恒)

实物库存管理。执行收发作业，回传实收/实发数量、批号、货位、效期与专门的【入账时间】字段。不持有价格，不写入 U8。

● 用友 U8 ERP

财务核算落点。生成采购入库单（暂估应付）与零售日报（发出商品）。审核由 U8 完成，业务系统不调审核接口。

● 核心原则：① 实物流以仓储为准；② 价格以业务系统合同订单为准；③ 仓储作业完成后生成 U8 单据；④ 一次执行生成一张 U8 单据；⑤ U8 严格先推入库后推出库，不允许负库存。

● 【入账时间】核心业务机制：宝应仁恒仓储系统中专门维护有【入账时间】字段。宝应仁恒仓储作业完成后，将该入账时间同步回传给业务系统，业务系统提取后原样推入用友 U8 作为单据入账日期。核心业务目的：专门用于解决用友 U8 财务想要提前入账的核算需求，确保账物时间严格勾稽。

三、请求单号与防重追溯字段

● 请求单号 (VoucherCode_Requester)：格式为 执行单号 + 拆单序号（如 BYRK-20261104-001-S1），U8 接口防重幂等判断键。

● 请求行 ID (VoucherBodyID_Requester)：格式为 执行单号 + 执行行号（如 BYRK-20261104-001-L1），仓储执行行与 U8 单据行 1:1 锚定。

● U8 单据编号 (VoucherCode)：采购入库单号（RK202611040012）与零售日报单号（LSRB-20261104-0008）。

四、金额计算顺序、容差与拆单规则

● 计算顺序：无税单价 = 含税单价 ÷ (1 + 税率) ➔ 无税金额 = 数量 × 无税单价 ➔ 税额 = 无税金额 × 税率 ➔ 含税总金额 = 无税金额 + 税额。

● 容差约束：单笔容差 0.06，整单容差 0.36。超出时调整最后一行税额，不改成交单价。

● 拆单规则：采购入库单按【供应商 + 仓库】拆单；零售日报按【客户】拆单（表体支持多仓库多货位）。

五、单据更正与退货处理

● 主数据变更：停用处理，不做物理删除。

● 单据错误更正：U8 弃审 ➔ 业务系统删除 ➔ 按正确数据重新新增（复用新增接口，无需开发修改接口）。

● 业务真实退货：一期暂缓开发，待与客户明确退货处置细则后在二期启动。

● 仓储作业撤销：仓储发起撤销 ➔ 双向校验能否删除 ➔ 校验通过调用删除接口；若已记账或期间已结账则转线下沟通。
